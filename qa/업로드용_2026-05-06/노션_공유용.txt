이번 주에는 기존 QA 결과를 단순 기록으로 두지 않고, 실제로 팀 내에서 공유하고 이후 수정/회귀 테스트까지 이어질 수 있는 형태로 정리하는 데 집중했음.

먼저 이전에 진행했던 52개 테스트 결과를 그대로 신뢰하기보다, 현재 기준에서 다시 설명 가능하고 재검증 가능한 구조로 바꾸는 작업을 진행했음. 이를 위해 QA 폴더를 배포/로컬, 정상입력/유해입력, 분석문서 기준으로 재정리했음. 정상 입력 대표 케이스로 `헬스장`을 잡아 배포 환경과 로컬 환경을 각각 확인했음.

그 결과 배포 환경에서는 `헬스장` 같은 정상 입력에서도 `500 Internal Server Error`가 발생했고, 유해 입력에서도 동일한 현상이 반복됐음. 그래서 현재 배포는 입력 정책을 평가하기보다는 생성 기능 공통 장애가 있는 상태로 해석하는 것이 맞다고 판단했음. 반면 로컬 환경에서는 매거진 생성과 DB 저장이 가능했기 때문에, 정책/검증 로직을 보기 위한 기준 환경으로는 로컬이 더 적합하다고 봤음.

이후 로컬 기준으로 유해 입력과 비정상 입력을 다시 테스트했음.
재테스트한 주요 입력은 아래와 같았음.
- 성적 표현: `남성의 나체`
- 위험폭력 표현: `생화학 테러`
- 정치선동 표현: `더불어민주당과 국민의힘을 지지하는`
- 차별혐오 표현: `흑인 노예`
- 비정상 입력: 잘못된 타입 입력, 매우 긴 문자열, 특수문자-only 입력

현재까지 확인한 결과는 위 입력들이 모두 `200 OK`로 생성 허용되었다는 점이었음.
즉 로컬 기준에서는 유해 입력 차단 로직, 타입 검증, 길이 검증, 형식 검증이 전반적으로 약하거나 사실상 부재한 상태로 볼 수 있었음.

이 결과를 바탕으로 이번 주에는 아래 문서/산출물을 정리했음.
- QA 결과 요약
- 실패 유형 묶음표
- 증빙 인덱스
- 역QA 포인트 정리
- 로컬 유해 입력 중간 결과
- 유해입력 분류 기준
- TC 초안 및 일부 기능 TC 작성본

특히 유해입력은 단순히 금지어 목록만으로 보기보다,
- 성적 표현
- 차별혐오 표현
- 정치선동 표현
- 위험폭력 표현
으로 나누고, 추가로
- 구조오류
- 긴문자열/형식오류
같은 비정상 입력도 별도로 분리했음.
이 기준은 이후 TC 확장과 회귀 테스트 기준으로도 바로 연결할 수 있도록 정리했음.

정리하면 이번 주 작업의 핵심은 아래와 같았음.
1. 기존 FAIL 케이스를 다시 설명 가능한 구조로 재정리했음.
2. 배포 환경은 정책 판정보다 공통 생성 장애 상태라는 점을 확인했음.
3. 로컬 환경에서는 유해 입력 및 비정상 입력 허용 문제를 다시 확인했음.
4. QA 결과를 증빙, 분류 기준, 역QA 문서까지 포함한 결과물 형태로 정리했음.
