# 역QA 포인트 정리

작성일: 2026-05-05

## 1. 현재 QA가 막히는 이유
- 입력 허용/차단 기준이 문서로 정리되어 있지 않다.
- 유해 표현, 정치 표현, 차별 표현, 성적 표현에 대한 정책 기준이 없다.
- 요청 스키마상 필수값과 실제 서비스 허용 범위가 일치하지 않는다.
- 잘못된 입력에 대해 `4xx`가 아닌 `500`이 발생하는 경우가 있어, 정책 문제와 서버 예외가 섞여 보인다.
- 배포 환경에서는 정상 입력에서도 `500`이 발생해, 입력 정책 QA 이전에 생성 기능 공통 장애가 해석을 방해한다.

## 2. 현재 확인된 구조적 문제
- 유해 입력이 `200`으로 허용되는 케이스가 다수 존재한다.
- 필수 구조값 누락에도 `200`으로 처리되는 케이스가 있다.
- 잘못된 타입 입력이 `500`으로 이어지거나, 반대로 그대로 `200`으로 허용되는 케이스가 있다.
- 필드명과 실제 기대값이 맞지 않는 계약 불일치가 있다.
- 길이/형식 검증 기준이 충분히 보이지 않는다.

## 3. 역QA로 복구해야 할 기준
- 어떤 입력을 허용할 것인지
- 어떤 입력을 제한할 것인지
- 어떤 입력을 차단할 것인지
- 차단 또는 제한 시 어떤 응답코드와 메시지를 반환할 것인지
- 구조 누락/잘못된 타입에 대해 어떤 검증을 할 것인지
- 너무 긴 문자열, 잘못된 형식 입력을 어디까지 막을 것인지
- 저장은 허용하되 노출만 제한할지, 입력 자체를 차단할지

## 4. 팀 논의가 필요한 항목
- 유해 키워드 차단 범위
- 정치/차별/성적/위험폭력 표현에 대한 운영 기준
- 입력 검증 실패 시 `4xx` 기준 정의
- 생성 실패와 정책 차단을 어떻게 구분해 사용자에게 보여줄지
- 배포/로컬/개발 환경 간 검증 기준을 어디까지 맞출지

## 5. 현재 QA 결과의 의미
- 이번 결과는 단순 버그 목록이 아니라, 서비스의 입력 정책 공백과 검증 구조 취약점을 드러낸 자료다.
- 따라서 다음 단계는 단순 재테스트가 아니라, 정책 미정 항목과 실제 결함 항목을 분리하는 작업이 필요하다.
- 이후 TC는 이 기준이 정리된 뒤 작성하는 것이 가장 효율적이다.
