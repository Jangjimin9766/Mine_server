# 2026-05-11 Input Guardrail Plan

## 목적
- 지난 QA에서 확인된 `유해 입력 허용`, `구조 검증 누락`, `잘못된 타입/형식 입력 처리 불일치`를 서버 단에서 바로 줄인다.
- 오늘 작업은 `1차 차단`과 `4xx 정규화`에 초점을 둔다.

## 이번 반영 범위
- `/api/magazines`
  - `topic`, `user_mood` 길이 제한 추가
  - 빈 값 차단
  - 유해 키워드, 폭력/자해/정치 선동 표현 1차 차단
- `/api/internal/magazine`
  - title, introduction, sections 등 필수 구조 검증
  - section/paragraph 단위 필수값 검증
  - URL 형식 검증
  - 잘못된 본문/타입 입력을 `400 Bad Request`로 정리

## 1차 차단 카테고리
- sexual
  - 노골적 성적 표현, 포르노/19금 관련 표현
- profanity
  - 강한 욕설, 모욕 표현
- hate
  - 성별/지역/인종 기반 혐오 표현
- violence
  - 테러, 살해, 직접적 폭력 조장 표현
- self_harm
  - 자살, 자해, 극단 선택 조장 표현
- drugs_or_scam
  - 마약 거래, 투자 사기성 표현
- political agitation
  - 정당/정권/대통령 대상 지지, 타도, 폭력 선동 결합 표현

## 정규화 원칙
- NFKC 정규화 적용
- 대소문자 무시
- 특수문자, 띄어쓰기, 구두점 제거 후 재비교
- 숫자 치환 일부 정규화
  - `1 -> i`, `0 -> o`, `3 -> e`, `5 -> s`, `7 -> t`
- 목적
  - `씨*발`, `s1bal` 같은 단순 우회 표현을 1차에서 다시 잡기 위함

## 현재 한계
- 키워드 기반만으로는 인용, 설명, 신고 문맥에서 오탐이 발생할 수 있다.
- 정치/혐오/자해 문맥은 최종적으로 별도 분류기 또는 리뷰 단계가 필요하다.
- 오늘 작업은 `명백한 케이스 차단 + malformed request 정리`까지를 목표로 한다.

## 다음 단계 제안
1. 차단/리뷰/허용 3단계 정책 문서 확장
2. 한국어 초성, 반복문자, 분절 우회어 규칙 강화
3. LLM safety classifier 또는 별도 moderation service 연동
4. QA 회귀 세트 50~100문장까지 확장
