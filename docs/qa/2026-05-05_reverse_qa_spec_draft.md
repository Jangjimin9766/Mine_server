# 역QA 기준서 초안

작성일: 2026-05-05

## 목적
- 기획서 부재 상태에서 `POST /api/internal/magazine` QA 판단 기준을 임시 복구한다.
- 기존 탐색적 QA 결과를 `판정 가능한 결함`과 `정책 확정 필요 항목`으로 나눈다.

## 기준 우선순위
1. 실제 구현 결과와 DB 저장 여부
2. 기존 API 가이드의 구조 정보
3. QA 관점의 안전/무결성 권고 기준
4. 팀 합의가 필요한 정책 항목은 `판단보류`로 둔다

## 확인한 입력/응답 축
| 항목 | 현재 관찰 | 임시 기준 |
|---|---|---|
| `title` | 누락 시 `200` 저장 케이스 존재 | 필수값으로 본다 |
| `subtitle` | 유해 키워드 혼합 시 `200` | 정책 확정 전까지 안전성 검토 필요 |
| `introduction` | 초장문 허용 | 최대 길이 정책 필요 |
| `coverImageUrl` | 잘못된 형식 허용 | URL 형식 검증 여부 결정 필요 |
| `tags` | 타입 불일치 시 `500` | 배열 타입 검증 후 `4xx`가 바람직 |
| `sections` | 빈 배열/문자열/필수 하위값 누락 케이스 존재 | 비어 있지 않은 배열 + 하위 필수값 검증 필요 |
| `user_email` | 실제 이메일 입력 시 `400 User not found` | 필드 의미와 기대 입력값 재정의 필요 |
| 유해 키워드/서사 | 여러 케이스가 `200` | 차단, 완화, 저장 금지 중 정책 확정 필요 |

## 판정 가능한 결함
아래 항목은 기획서가 없어도 결함으로 보기 충분하다.

| 분류 | 판정 근거 | 대표 케이스 |
|---|---|---|
| 타입 오류가 `500`으로 노출됨 | 잘못된 요청은 서버 오류보다 검증 실패로 처리되어야 함 | `AN-2`, `AN-7` |
| 필수 구조 누락인데 `200` 처리 | 섹션과 제목이 핵심 구조이므로 무결성 훼손 | `AN-1`, `AN-5`, `AN-6`, `AN-8` |
| 동일 비정상 패턴이 3회 반복 재현 | 우연성보다 고정 결함 가능성 높음 | `AUTO-*`, `HK-*`, `HC-*` |

## 정책 확정이 필요한 항목
아래 항목은 구현 수정 전 `기획 또는 정책 합의`가 먼저 필요하다.

| 항목 | 필요한 결정 |
|---|---|
| 유해 키워드 입력 | 즉시 차단할지, 완화 생성할지, 저장만 금지할지 |
| 자해/폭력/차별 서사 | 차단 범위와 응답 메시지 기준 |
| 제목/소개글 길이 제한 | 필드별 최대 길이 |
| 이미지 URL 형식 | 외부 URL 허용 범위와 검증 방식 |
| `user_email` | 실제 이메일인지 내부 식별자인지 |

## 임시 테스트 판정 규칙
- `500` 발생: 우선 FAIL
- 필수 구조 누락 후 저장됨: 우선 FAIL
- DB에 저장되면 안 되는 위험 입력이 저장됨: 우선 FAIL
- 정책 미정 항목은 `판단보류`로 분리하되, 저장 여부는 반드시 기록

## 이번 주 문서화 대상
1. 기존 52건을 `PASS / FAIL / 판단보류`로 재라벨링
2. 각 케이스에 `DB 저장 여부` 열 추가
3. `정책 확정 필요` 항목만 따로 뽑아 팀 확인 요청
4. 확정된 항목부터 회귀 테스트셋으로 고정

## TC에 추가할 필수 열
| 열 이름 | 설명 |
|---|---|
| `TC ID` | 고유 식별자 |
| `입력 유형` | 정상 / 비정상 / 유해 / 경계값 |
| `요청 필드` | 핵심 입력 요약 |
| `기대 결과` | 상태코드 + 응답 방향 |
| `실제 결과` | 상태코드 + 응답 요약 |
| `DB 저장 여부` | 저장됨 / 미저장 / 확인필요 |
| `판정` | PASS / FAIL / 판단보류 |
| `판단 근거` | 구현, DB, 정책, 가이드 중 무엇인지 |
